# 一日游方案（只有当日游玩 + 聚餐）

本技能默认产出"双日上午双路线"方案，但同样支持**一日游**——只有第一天游玩与聚餐，没有第二天。按本文件裁剪，不要硬套双日结构。

## 与双日版的结构差异

| 部分 | 双日版 | 一日游版 |
|---|---|---|
| header 副标题 | "次日上午 前海/市民中心 双线任选" | 只写当日主线，如"XX 集合 → XX 游览 → XX 聚餐" |
| nav | 天气/场地/首日下午/晚宴/次日/地图/一览 | 天气/场地/行程/聚餐/地图/一览（**去掉"次日"**） |
| 行程 section | day1（下午时间轴）+ day2（双路线） | 一个 `day1` 时间轴覆盖全天（上午/下午/晚上） |
| 路线卡 | 次日两条 `route a/b` | 不需要；若当日有多个候选段，用时间轴内的"二选一"块 |
| 一览表 | 两日 + 双线分组 | 单日时间顺序，无需分线组 |
| 地图 | 首日下午 + A/B 线三色 | 单一路线 + 可选点 |

## 具体裁剪做法

1. **导航**：从模板的 `<nav>` 中删掉 `<a href="#day2">` 那一项；其余按实际 section 保留。导航高亮脚本用 `IntersectionObserver` 自动适配，无需改脚本。
2. **section 列表**：保留 `weather` / `venue` / `day1` / `dinner`（或并入 day1）/ `routemap` / `overview`；**删除 `day2`**。若没有单独晚宴环节，`dinner` 也可并入 `day1` 末尾的时间轴事件。
3. **时间轴**：把 `day1` 的事件从"下午"扩展为全天——上午集合、上午游览、午餐、下午游览、晚餐、夜间自由活动（可选），每个事件仍用 `.ev` > `.t`(`time`/`name`/`dur`) + `p` + `line`/`chips`。
4. **可选点**：一日游时间更紧，所有非核心点更要明确标"可选/视时间而定"（放时间列），不要塞满主线。
5. **地图**：按 `references/map.md` 建点，但 `routes` 只做一条主线（虚线段=坐车、实线段=游玩）；`VIEWS` 保留"全部/主线"两个按钮即可，可删次日 A/B 按钮。
6. **一览表**：去掉双线分组与 `↳` 缩进，按时间顺序单行排列；列仍是日期/时间、地点、安排与看点、交通衔接、停留。

## 文案注意

- 副标题、主题诗解题、footer 都不要出现"次日/双线/任选"等双日措辞。
- 主题诗仍按 `references/content.md` 的七律套路；若为纯一日聚会，合句可只祝再会，不必写"明年津门"。
- 聚餐作为当日压轴，写清时间、地点、包间/台位、预算与来源（见 `references/sourcing.md`）。

## 验证清单（一日游）

- `document.querySelectorAll('#nav a')` 无"次日"链接，且点击能滚动到对应 section。
- `document.querySelectorAll('section').length` 与预期一致，无空的 day2 占位。
- 时间轴事件数、图片数、主题诗四句、标语四枚均正常。
- 三项交互脚本（zoom/导航高亮/主题切换）仍在。
- 无横向溢出；HTML 与 MHTML 同步。
