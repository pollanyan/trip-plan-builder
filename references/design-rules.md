# 方案生成十条规则（每次生成必遵守）

这些规则来自实战迭代，是"一次成型、减少反复修改"的关键。生成任何行动方案前先读本文件，逐条对照。

## 1. 文件名与标题一致、标题活泼

- 文件名中 `_日期` 前部分必须与页面标题一致（可去标点），如标题「羊城两日 · 广深同学畅聊畅游行动方案」→ 文件名「羊城两日 · 广深同学畅聊畅游行动方案_1226.html」。
- 标题要活泼、有画面感，包含「畅聊畅游」这类能点出聚会氛围的词（参考深圳版「鹏城两日 · 广深同学会畅聊畅游行动方案」）。
- 生成后核对 `document.title` 与文件名主干一致。

## 2. 聚焦目的地，不预设出发地专属信息

- 删除出发城市专属 chip（如「深圳北集合」「高铁往返」等）；chip 写目的地、集合时间、核心餐厅、氛围词。
- 参考深圳版点明**酒店、饭店、首要游玩地点**（正文与 chip 都要有）。
- 结合目的地当期热点（用户指定或自行搜索，见 `hotspots.md`）；热点须与出行日期有交集，已结束的活动不写入。
- 跨城交通移到独立章节（见第 4 条），不要散落在 header/chip。

## 3. 图片精准匹配标题与内容（按四类规格）

从小红书、大众点评、携程及搜索引擎检索，**逐张看图核对**后再用，不靠标题猜：

| 类别 | 大图 | 3 张小图 |
|---|---|---|
| 酒店 | 1 张外观/外景 | 大堂、房间、早餐厅；缺失时用「楼上视野」等替代并注明 |
| 饭店 | 1 张主打宣传彩图 | 外观/外景、厨房厨师或大厅就餐、包间与特色菜品 |
| 景点 | 1 张全景 | 3 张不同视角/网红打卡点，匹配白天/夜景 |
| 场馆 | 外观全景 | 特色外景视角、馆内特色展品 |

- 图注要写清画面内容与用途；缺失的真实图用开放图库（Wikimedia Commons）兜底并如实标注来源。
- 小红书搜索结果常混入文字封面/攻略图，逐张筛查剔除。

## 4. 跨城交通单独成章 + 推荐方案

- 新建 `transport` section，列「推荐」与「备选」，推荐项明确标注 ✅。
- 覆盖高铁、城际、自驾等方式，给时长、票价、衔接（到站后地铁/打车）。
- 写明本地同学如何会合、返程如何衔接。

## 5. 夜间安排给多种选择

至少提供：回酒店、回家、夜逛、夜场（喝茶打牌或夜宵啤酒）；夜场标「可选 · 自愿参加」，并提示安全与返程。
- **标签与正文要能并排不重叠**：`.kv` 是两列 grid（标签列 + 内容列），标签列宽必须能容纳最长标签；**禁止**给标签加 `white-space:nowrap` 却仍用固定的窄列宽——文字会溢出压到正文上（见第 11 条）。
- 一览表里也要有对应的「20:30 起（可选 · 自愿参加）· 分流 · 夜间安排」行。

## 6. 路线图片随行程推进

- 到景点给 1 大 3 小；小景点只给 1 张。
- 集中片区（如 CBD 中轴线）在路线卡标题下放 1 大 3 小展示全景与主要打卡点。
- 图片顺序与行程时间顺序一致。

## 7. 在线路线示意地图

- 生成独立地图页（见 `map.md`），在方案中放**截图 + 图例 + 在线地图链接**（`target="_blank"` 指向同目录地图页）。
- 图例编号、截图编号、在线地图编号三处一致，用简单数字 1–N，字号与相邻文字一致。

## 8. 章节名用「温馨提示」

- 不用「需提前确认事项」，统一叫「温馨提示」。
- 内容仍是订票/订位/预约/天气/路线选择等待办。

## 9. 全程一览表标注网红打卡点与可选点

- 大众公认网红打卡点或重要人物打卡点：**把地名本身**加粗绿色 `.apec`（如 `<span class="apec">花城广场</span>`），**不要**只把「网红打卡」四个字加绿——那样等于没告诉读者到底是哪个点。
- 「可选 / 视时间」景点单列成行，时间列写「XX:XX 起（可选）」或「↳ 可选」，安排列以「可选：/ 视时间而定：」开头；且**前文正文已介绍、顺路可达**——不要在表里凭空出现。每条备选路线至少给 1 个顺路可选点。
- **两条独立备选路线必须各自用组名开头**（如「路线 A · 老城岭南 09:00–13:30」「路线 B · 珠江江心 09:00–13:30」）。`↳` 只表示**同一条路线内部的后续站点或可选点**，绝不能用来引出第二条独立路线——那会让人误以为 B 线是 A 线的子项。
- 一览表底部 note 说明绿色含义与可选口径。

## 10. 增加「打卡地一览」

- 新增 `checkin` section，表格列出打卡地名与极简简介。
- 有特别事件（如 APEC）时列事件相关打卡地；无特别事件时选大众公认网红打卡点。
- 所列地点须与行程或备选对应，不列无关地点。
- **整章都是打卡地，表内不再对「打卡地」类型列或地名列做任何加粗/加绿**——否则满屏高亮失去意义，与其它章节的绿色标注规则区分开（深圳版反复强调过）。

## 11. 两列布局与表格的 CSS 约束

**依赖边界**：正常生成方案**不需要任何外部 Web 开发技能**——`assets/plan-template.html` 已固化全部 CSS 最佳实践，本 skill 可独立使用（也是跨平台安装的前提）。只有**修改模板设计系统本身**（改 CSS、加新交互组件、遇到新的布局 bug）时，才应先查现代 Web 最佳实践指南再动手，避免凭记忆写出过时或易碎的写法。

- `.kv` 这类「标签 + 内容」两列，用 intrinsic sizing：`grid-template-columns:max-content 1fr`，让标签列按最长标签自适应；标签可 `white-space:nowrap`，但**列宽必须同步放开**。禁止「固定窄列 + nowrap」的组合——文字会溢出重叠。
- 验证方法：浏览器量每个 `.k` 的 `getBoundingClientRect().right` 是否 ≤ 同行 `.v` 的 `.left`（留 gap），不能只看截图。
- 重构 HTML 表格/区块时，**不要用 `find('<tbody>')` 这类无属性匹配**——预览工具会注入 `data-page-node-id`，标签实际是 `<tbody data-page-node-id="...">`，匹配失败会切坏 section。用正则兼容属性，或按 `<section id="...">` 锚点整体替换；改完立刻核对 section 数量与 id。
- 常见语义错误：上午时段不写「夜景」；「↳」不用于并列独立项（见第 9 条）。

## 生成后自检

按 `pitfalls.md` 的验证清单用浏览器检查：章节/导航一致、图片全加载 0 损坏、三处编号一致、无深圳/旧城市专属残留、**kv 列不重叠、一览表有可选行且两条路线各自成组、打卡地一览无高亮**、无横向溢出、MHTML 同步。
