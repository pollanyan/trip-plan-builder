# 登录平台协作流程（必须遵守）

本文件把"需要登录的平台如何请用户登录、如何验证"固化为可执行流程。来自实战：用户会分多次确认登录（先登录小红书、再要求打开其它平台、最后统一确认），必须逐步跟进而不是一次性假设全部搞定。

## 核心原则

1. **逐个平台打开登录入口**：不要只提示"请登录"，要主动用浏览器为每个所需平台打开登录页，让用户能直接扫码。
2. **分次确认也能推进**：用户说"某平台登录好了"时，先验证该平台，验证通过就先用它继续；其余未登录平台继续等待，不要让整个任务空转。
3. **口头确认后必须自行验证**：用户说"已登录"不等于真的登录成功，必须用浏览器检查页面标识。
4. **验证失败要明确告知**：告诉用户哪个平台仍未登录、页面停在哪，不要含糊说"登录有问题"。
5. **不跳过、不降级**：未验证通过的平台，绝不执行依赖其登录态的步骤（查价/取图/抓取），也不要改用其它来源顶替——除非用户明确说"不登录，用公开信息即可"。
6. **从暂停处继续**：登录完成后回到原任务断点，不重头开始。

| 平台 | 打开的 URL | 备注 |
|---|---|---|
| 小红书 | `https://www.xiaohongshu.com/search_result?keyword=<关键词>` | 打开搜索页即可看到是否需登录；用户扫码后此页会刷出笔记 |

## 登录态验证判据（读 `document.body.innerText`）

用 `evaluate_script` 检查页面文字，按下列判据判断：

- **小红书**：
  - 未登录：`"登录后查看搜索结果"` 且 `.note-item` 数量 = 0
  - 已登录：有"我"/"消息"等个人入口，`.note-item` > 0，`needLogin:false`
- **携程 PC**：
  - 未登录：URL 含 `passport.ctrip.com/user/login`，或出现"账号密码登录""扫码登录"
  - 已登录：URL 回到 `hotels.ctrip.com`，出现"我的订单"，无登录表单
- **飞猪**：
  - 未登录：页头出现"注册 登录"
  - 已登录：页头出现你的账号名与"退出"
- **大众点评**：
  - 未登录：URL 含 `account.dianping.com/pclogin`，出现"请登录/注册"
  - 已登录：URL 回到 `dianping.com`，无登录表单，有"个人中心/我的"

验证示例（通用）：

```js
() => {
  const t = document.body.innerText;
  return {
    url: location.href.slice(0, 60),
    loginForm: (t.match(/(请登录|登录\/注册|登录后查看|账号密码登录|扫码登录)/g) || []).slice(0, 2),
    loggedSign: (t.match(/(退出|我的订单|个人中心|我的携程|消息|我)/g) || []).slice(0, 3),
    cards: document.querySelectorAll('.note-item').length
  };
}
```

## 标准协作话术与步骤

1. 检测发现需登录 → 暂停，明确列出"哪个平台未登录，请扫码登录"。
2. **主动打开其余所需平台的登录页**（用 `new_page`，一个平台一个标签页），方便用户一次性登录。
3. 用户说"X 已登录"→ 立即验证 X；通过则继续用 X 的素材/数据，未通过的其它平台继续等待。
4. 用户说"都已登录"→ 逐个验证全部平台，把结果用表格反馈（✅已登录 / ❌未登录）。
5. 全部验证通过后，从暂停处继续。

## 实战记录（本次）

- 小红书：先未登录 → 用户扫码 → 验证通过（22 条笔记）→ 取到广州塔/花城广场/省博/陈家祠/珠江新城实拍 15 张。
- 飞猪：打开后已登录（页头显示账号名与"退出"）。
- 携程：先打开移动版被用户纠正 → **改开 PC 版** → 用户登录 → 验证 URL 回首页、"我的订单"出现。
- 大众点评：先跳扫码页 → 用户登录 → 验证 URL 回 `dianping.com`、无登录表单。
